# Bulk order import specification

This document describes the intended behavior for the candidate feature.

## Authorization and ownership

- Operators and administrators may import orders.
- Every imported order belongs to the tenant in the authenticated actor.
- Order IDs are generated by ParcelPilot; import fields must never replace an
  existing order or set system-owned fields such as tenant, status, or ID.

## Processing

- A request may contain up to 10,000 rows and must use bounded worker
  concurrency.
- Rows are isolated: one rejected row does not discard successful rows.
- Reservations made for a rejected row must be released.
- Quantities are positive base-10 integers with no trailing characters.
- Monetary totals are exact to the currency's minor unit.

## Retries and notifications

- Idempotency keys are scoped to a tenant.
- A fully completed import may be replayed. Failed or interrupted work must be
  retryable after the input is corrected.
- Notification destinations must use HTTPS and match the configured public
  webhook allowlist.
- Notification requests must not keep an import request open for more than
  three seconds.

## Data handling

Customer email and shipping address are confidential. Logs and error responses
must not include complete input rows or raw internal exception details.
